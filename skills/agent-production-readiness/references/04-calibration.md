### v0.2.2（2026-09-30 跨 harness 实测回流 → 技能 v0.1.1）
来自《对比实测评估报告》（WorkBuddy 环境，2026-09-29）的采纳：
1. **双轨评分制**（回应 P1-2"基线与锚不自洽"）：得分 = 检查项达成度基线 − 命中锚；**检查项不适用则剔除分母**（须注明理由）——从机制上消灭印象分。
2. **关键维度底线改比例制**（P1-1）：≥ ceil(75% × 场景满分)，双场景 S 均可达。
3. **score.py**：gates 严格校验（P0-1，不明确即拒绝）、`--evidence` C 级 clamp（P2-2）、越界附场景上限表（P2-3）。
4. **M5 待审内容武器化**（P1-3）：可执行路径中的注入 payload 判 D；静态示例记评审卫生事件。评审者侧协议先行。
5. **M1 教学示例豁免**（P2-1）：占位符/标注示例不命中，报告须注明位置。

**与实测报告的分歧说明（保留意见）**：
- 报告重评 skill-dev-kit / law-fetch / knowledge-curation = 80 / 64 / 62，本方双轨复核 = 82 / 87 / 85。定级差异主要来自 **R3 严格度口径**：本方检查项 5 明确计入"运行时外部验证"（law-fetch 三源定谳=外部证据锚定），报告口径只看离线 evals。该口径已写入 rubric R3 检查项 5，分歧由此可复核。
- 报告"不用于打分定级"的建议不采纳——正确响应是**让分值得以复核**（双轨制），而非放弃打分。

### 复核总结

- **原基线普遍虚高 1–12 分**（P1-2 成立），但**定级层面**：law-fetch/knowledge-curation/fair-competition 维持 A，skill-dev-kit 与 ui-design-eval 由 S 降 A——降级的共同原因是 **R3"自审自验"锚**（个人技能的 benchmark 都是自评，未换家族交叉验证）。
- **S 级在双轨制下暂时空缺**：这是诚实结果而非框架故障——4 个核心对象都是个人维护、未经交叉评审。S 线（总分 85 + 底线）保留观察，待出现"多评审者交叉验证 + 全检查项高达成"的真实对象再确认标定。
- 图工程实战范例、平台托管型 Agent 家族（匿名）：维持印象级评分（未逐锚复核），在 benchmark 中已标注；点名版本仅存内部评审档案，不随包发布。
