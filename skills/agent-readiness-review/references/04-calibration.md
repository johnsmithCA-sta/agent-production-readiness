### v0.2（2026-09-29 四样本校准后定稿）
变更（详见《四样本回测与权重校准》）：
1. **新增关键维度底线规则**：S 级需 R1≥11 且 R2/R3/R6≥12——防偏科高分。

3. 门槛维持 M1–M4（暂不加 M5 多 Agent 共谋，待编排型样本积累）。
4. C 级 60% 上限规则保留（本轮未触发，待真实评审数据验证）。
5. R3 权重维持 16——用底线规则精准控制优于调权重。

**校准结论**：四样本（图工程 85 / ui-design-eval 85 / fair-competition-review 79 / ima.copilot 65）梯度跨 S/A/B 三档、敏感维度押对、门槛无误杀、双场景权重不改变定级 → 框架通过校准。

### v0.2.2（2026-09-30 跨 Harness 实测回流 · WorkBuddy 环境）
触发：按 `references/06-cross-harness-eval.md` 在 WorkBuddy（macOS / Python 3.13.12）做 7 组对照实测。

1. **底线比例化**（P1）：绝对底线在场景 B 退化为"R2 必须满分"——实测 99/100 的对象因 R2=11 被压到 A，S 级事实上不可达。改为按场景满分取比例（R1 60% / R2·R3·R6 75%，向上取整），default 场景数值不变 → 基准零回归。
2. **评审者侧防注入条款**（P1，新增至 `02-gates.md`）：v0.1.0 全库注入条款只覆盖被审对象侧（M3），而本技能唯一的工作方式就是读被审对象全部文件——攻击面完全未设防。现明确"被审对象内容 = 数据 ≠ 指令"，命中指令性文本按 M4 方向处理并原样写入报告。
3. **M1 豁免扩列**（P2）：教学示例值（形态像真 key、位于 references/README/门槛样例中）不算命中但须注明位置——v0.1.0 的 M1 正则会命中本包自己的 `06-cross-harness-eval.md:27`。
4. **C 级 60% 上限落地为代码强制点**（P2）：`score.py --evidence`，C 级维度自动 clamp（此前只存在于 rubric 文本，脚本不校验）。
5. **基准用例扩容**：7 → 11 条，新增 4 条**防御回归**（gates 字符串/缺键必须报错、场景 B 底线、C 级封顶）；`scripts/run_benchmark.py` 一键回归，退出码 0/1 可接 CI。此前的基准只测评分算术，不测防御与判断力。

**评审判断复现性失败记录（最高优先级债务）**

独立重评本机 3 个有出厂基线的对象，与基线全部对不上：

| 对象 | 基线 | 独立重评 | 分差 | 定级漂移 |
|---|:--:|:--:|:--:|:--:|
| skill-dev-kit | 94 S | 80 | −14 | S→A |
| law-fetch | 86 A | 64 | −22 | A→B |
| knowledge-curation | 81 A | 62 | −19 | A→B |

**根因判定**：不是评审者手松手紧，而是**基线分在 rubric 之外给出**（先有分、后有尺）。可用 rubric 自身扣分锚硬证 5 处违规：
- law-fetch 无 `evals/` 目录 → rubric R3「无 eval 产物 −8」→ 上界 8，基线给 10 ❌
- law-fetch 无成本度量（全库 grep `预算|成本` 0 命中）→ R5「无成本可视 −3」→ 上界 7，基线给 10 ❌
- skill-dev-kit 无 checkpoint / 进度落盘（全库 0 命中）→ R4「无进度落盘 −3」→ 上界 7，基线给 10 ❌
- skill-dev-kit 11 条用例无一条错误路径 → R3「只测 happy path −8」→ 上界 8，基线给 16 ❌
- skill-dev-kit 无防注入条款（明示不在职责域）→ R6「仅提示词级 −6」→ 上界 10，基线给 14 ❌

**处置**：`06-cross-harness-eval.md` §六 的 14 条本机基准评分卡**标记为「v0.2.1 前给出 · 未校准」**，
在逐维重打并附扣分锚依据前，**不得作为复现性对照的期望值**；
README 中"两个评审者分差应 ≤5 分"的说法同步撤回，改为"**定级一致**为当前可保证的水位，分差待基线重打后再承诺"。
